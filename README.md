## 项目简介

一台**独立运行**的手持测光表。

拍胶片的时候，相机机身没有测光，或者手机测光 App 用起来别扭 —— 要解锁、要开 App、要等广告、光线暗一点就测不准。所以我想要一个**按一下就能用**的小设备：开机、对着目标、读数，完事。

**核心思路：**

```
环境光 (BH1750) → 光照度 Lux
                     ↓
              EV100 = log₂(Lux / 2.5)
                     ↓
        EV = EV100 + log₂(ISO / 100) + 滤镜补偿
                     ↓
   已知光圈 → 反推快门   |   已知快门 → 反推光圈
                     ↓
              显示在 OLED 上，旋钮调节
```

**项目定位：** 不追求复杂，追求**真实可用**。

## 功能特性

- **一键测光** —— BH1750 数字光照传感器，每秒刷新，量程覆盖室内到烈日（~1 lx 至 65000 lx）
- **EV 自动计算** —— 依据 `EV100 = log₂(Lux / 2.5)`，自动纳入 ISO 与滤镜衰减
- **五种拍摄档位**，对应真实相机的操作逻辑：

  | 档位 | 名称 | 说明 |
  |---|---|---|
  | `P` | 程序优先 | 你动过的项固定，其余由程序补齐 |
  | `A` | 全自动 | 短按一次，直接给出可用参数 |
  | `AV` | 光圈优先 | 定死光圈，自动求快门 / ISO |
  | `TV` | 快门优先 | 定死快门，自动求光圈 / ISO |
  | `M` | 全手动 | 全部手调，只显示曝光偏差 |

  另外长按旋钮可进入模式选择页，选中 `OFF` 即关机（关机不属于拍摄档位）。

- **曝光偏差实时指示** —— 顶栏直接告诉你当前参数偏了几档（`+1.0` 过曝 / `-0.5` 欠曝 / `OK` 准确）
- **安全边界保护** —— 快门不慢于 1/250、ISO 不高于 6400、光圈不高于 f/8，越界时偏差闪烁提醒。**防止新手拍出一堆糊片。**
- **滤镜补偿** —— 内置 ND2 / ND4 / ND8 / ND16 / ND32 / CPL 六档滤镜补偿
- **自动对比度** —— 环境越亮屏幕越亮，暗光下不刺眼
- **电池计时显示** —— 左上角四格电池图标，按运行时长估算剩余电量，空电闪烁提醒
- **息屏省电** —— 30 秒无操作自动息屏，旋钮一转立即唤醒

## 接线说明

### 引脚分配

| 功能 | ESP32-C3 引脚 | 说明 |
|---|---|---|
| OLED SDA | **GPIO4** | I2C 数据线，与 BH1750 共用 |
| OLED SCL | **GPIO5** | I2C 时钟线，400 kHz |
| BH1750 SDA | 共用 GPIO4 | I2C 地址 0x23 |
| BH1750 SCL | 共用 GPIO5 | |
| EC11 A | **GPIO6** | 编码器 A 相 |
| EC11 B | **GPIO7** | 编码器 B 相 |
| EC11 PUSH | **GPIO10** | 按压开关 |

### I2C 总线并联布线的思路

屏幕和传感器**都走 I2C**，所以它们可以挂在**同一条总线**上 —— 这就是为什么只需要 GPIO4 / GPIO5 两根线，就能同时驱动两个设备。

```
              ┌──────────────┐
              │  ESP32-C3    │
              │              │
   GPIO4 ─────┤ SDA          │
   GPIO5 ─────┤ SCL          │
              └──────┬───────┘
                     │
          ┌──────────┴──────────┐
          │  I2C 分线器 (1→3)    │
          └──┬────────┬─────────┘
             │        │
        ┌────┴───┐ ┌──┴─────┐
        │ OLED   │ │ BH1750 │
        │ 0x3C   │ │ 0x23   │
        └────────┘ └────────┘
```

**用的是"一分二 / 一分三"的 I2C 分线器**，把两三个设备并联挂到总线上。

**为什么这样接是安全的：**

1. **I2C 是总线协议**，天生支持多设备共存 —— 每个设备有独立地址（OLED 是 0x3C，BH1750 是 0x23），主控靠地址寻址，不会打架
2. **所有设备统一 3.3V 供电** —— ESP32-C3 是 3.3V 逻辑，屏和传感器也都支持 3.3V，**全部接 3.3V 而不是 5V**
3. **SDA / SCL 各需要一根上拉电阻**（模块通常自带），多设备并联时共用即可

> ⚠️ **这里有个新手最容易犯的致命错误**：把 5V 接到 3.3V 器件的供电脚上，一插就烧板。我在接线前专门把每个模块的电压要求查了一遍，**ESP32-C3 / SH1106 / BH1750 全部是 3.3V 逻辑**，所以供电统一走 3.3V，坚决不碰 5V。

### 供电与充电

```
USB 5V ──→ LTH7 充电模块 ──→ 锂电池 (3.7V)
                                    │
                                    ↓
                              ESP32-C3 3V3 引脚
                                    │
                          ┌─────────┴─────────┐
                        OLED              BH1750
```

LTH7 负责把 USB 的 5V 转成合适的充电电压喂给锂电池，锂电池再给整个系统供电。

> ⚠️ **调试阶段的安全红线：电脑 USB 供电和电池供电必须物理隔离。**
> 调试时要么只插 USB（拔掉电池），要么只用电池（拔掉 USB）。**绝不两个电源同时接** —— 否则两个电源会互相"顶"，轻则读数乱跳，重则烧稳压芯片。

## 编译与烧录

### 环境要求

- **Arduino IDE**（或 arduino-cli）
- **ESP32 开发板支持包**（Espressif，测试版本 3.3.x）
- **U8g2** 图形库（库管理器搜索安装）

### 开发板设置（关键）

| 项目 | 值 |
|---|---|
| 开发板 | **ESP32C3 Dev Module** |
| **USB CDC On Boot** | **Enabled** ⚠️ |
| Flash Size | 4MB |
| Upload Speed | 921600 |

> ⚠️ **`USB CDC On Boot` 必须设为 Enabled**，否则串口没有任何输出，你会以为板子坏了。这个问题困扰了我很久，详见下方[故障分析](#2-usb-cdc-on-boot-设置错误导致串口无输出)。

### 烧录步骤

```bash
# 编译
arduino-cli compile -b esp32:esp32:nologo_esp32c3_super_mini:CDCOnBoot=cdc .

# 烧录（COM 口按实际改）
arduino-cli upload -p COM3 -b esp32:esp32:nologo_esp32c3_super_mini:CDCOnBoot=cdc .
```

如果烧录失败，尝试**手动进入下载模式**：

1. **按住 `BOOT` 键不放**
2. **按一下 `RESET` 键**
3. **松开 `BOOT` 键**
4. 此时板子进入下载模式，再点上传

## 操作指南

### 开关机

- **长按旋钮（1.5 秒）** → 开机
- **开机后长按** → 进入模式选择页，转到 `OFF` 并按下确认 → 关机

### 主界面操作

| 操作 | 效果 |
|---|---|
| **短按** | 切换当前编辑的字段（SHUTTER → APERT → ISO → FILTER） |
| **旋转** | 修改当前字段的值 |
| **长按** | 进入模式选择页 |
| **30 秒不动** | 自动息屏，转一下旋钮唤醒 |

### 屏幕布局

```
┌────────────────────────────────────┐
│ 🔋  +0.3 │ 320 lx │            M   │   ← 电池 / 偏差 / 光照 / 模式
├────────────────────────────────────┤
│ SHUTTER                    1/125   │
│ APERT                      f/5.6   │
│ ISO                          100   │
│ FILTER                      NONE   │
└────────────────────────────────────┘
```

- **偏差 `+0.3`** —— 当前参数比"正确曝光"过曝 0.3 档；`OK` 表示刚好
- **光照 `320 lx`** —— 当前环境光照度
- **模式 `M`** —— 当前档位

## 开发中遇到的问题与解决办法（故障分析）

**这一节是整个项目我最想讲的部分。** 因为说实话，写出能跑的代码不难，难的是**东西不工作时，你能不能在没有任何人告诉你的情况下，一步步把它弄明白**。

下面每一个问题，都是我自己踩、自己查、自己解决的。

---

### 1. 环境限制：宿舍不能用电烙铁 → 全程零焊接

**问题：** 宿舍明令禁止使用电烙铁（火灾风险），但我需要把一堆模块连起来。

**解决：** 全程采用**面包板 + 25 根杜邦线 + I2C 分线器 + 模块化配件**的纯插接方案。

- 所有元件都是**带排针的成品模块**，直接插面包板
- 用 **25 根杜邦线**连接各模块与主控，接线直观、随时可改
- I2C 分线器把屏幕和传感器并联到同一条总线上

**收获：** 被迫选择了模块化方案，结果反而**更适合新手** —— 接线直观可见、错了立刻能改、拆装方便。而且这个方案有个意外好处：**调试时想断开某个模块，拔一根线就行，不用动焊台。**

---

### 2. USB CDC On Boot 设置错误 → 串口完全没有输出

**问题：** 板子插上电脑，设备管理器里能看到串口，但**串口监视器里一个字都没有**。程序像是根本没跑。

**排查过程：**

1. 首先怀疑代码 —— 把 `Serial.begin(115200)` 检查了无数遍，没问题
2. 怀疑板子坏了 —— 换了个 USB 口，同样无输出
3. 怀疑线材 —— 换线，一样
4. **开始查资料** —— 搜"ESP32-C3 串口无输出"、"ESP32-C3 Serial not working"

**根因：** ESP32-C3 **没有外置的 USB 转串口芯片**（不像 Arduino UNO 有 CH340）。它用的是**芯片内部的原生 USB 外设**。当 `USB CDC On Boot` 关闭时，USB 口只用于烧录，**`Serial` 走的是 UART0 而不是 USB** —— 所以你在串口监视器里当然什么都看不到。

**解决：** 在 Arduino IDE 的 **工具 → USB CDC On Boot → 选择 Enabled**，重新编译烧录。串口立刻正常。

**教训：** **不是所有 ESP32 开发板都一样。** ESP32-C3 的 USB 架构和 ESP32 经典款、Arduino 完全不是一回事。"设备管理器能看到串口"≠"串口能收发数据"。

---

### 3. Windows 下端口"跳来跳去" + 无限重启

**问题：** 板子插上后，串口在设备管理器里**一会儿 COM3、一会儿 COM4**，而且板子**反复重启**，根本连不上。

**排查过程：**

1. 观察设备管理器，发现每次重启串口号都会变
2. 怀疑是驱动问题 —— 重新装了驱动，没用
3. 怀疑电源不稳 —— 换了数据线，改善但没根治
4. **意识到问题可能在启动模式**

**根因：** 两个问题叠加：

- **ESP32-C3 的启动模式由 strapping 引脚（GPIO2 / GPIO8 / GPIO9）在上电瞬间的电平决定。** 如果这些引脚接了外部电路、或者悬空电平不确定，芯片可能反复进入异常启动状态，于是不断重启
- **每次重启 USB 重新枚举，Windows 就分配一个新端口号** —— 这就是"端口跳来跳去"的原因

**解决：** **手动进入下载模式**：

```
按住 BOOT → 按一下 RESET → 松开 BOOT
```

这样能强制芯片进入下载模式，稳定烧录。烧录完成后按 RESET 正常运行。

**教训：** ESP32 系列的 strapping 引脚**不是随便用的**。如果你的项目要接额外电路，**避开 GPIO2 / GPIO8 / GPIO9**，否则会遇到各种莫名其妙的启动问题。这是 ESP32 的经典"玄学坑"。

---

### 4. 总线冲突与 I2C 接线逻辑

**问题：** 屏幕和传感器都要接，引脚不够用，而且我一开始完全不懂 I2C 到底是什么。

**排查/学习过程：** 查资料搞懂了 I2C 的本质 —— **它是一根总线，多个设备可以挂在上面，靠地址区分。**

**解决：**

1. **确认两个设备的 I2C 地址不冲突**（OLED 0x3C，BH1750 0x23，没问题）
2. **用 I2C 分线器**把两个设备物理并联到 SDA / SCL 上
3. **供电统一走 3.3V**，绝不用 5V

**收获：** 不只解决了接线问题，还真正理解了 **I2C 总线的设计思想** —— 用两根线挂多个设备，靠地址寻址，这正是嵌入式系统里最优雅的设计之一。

---

### 5. 电池与充电模块的安全隔离

**问题：** 调试阶段，如果电脑 USB 和锂电池**同时供电**，会怎样？

**分析：** USB 提供 5V，电池提供约 3.7~4.2V，两个电源会在供电节点上**互相"顶"**：

- 电压高的会往电压低的倒灌电流
- 稳压芯片可能承受反向电压
- 轻则读数乱跳、程序跑飞，重则烧毁器件

**解决：** **物理隔离，绝不含糊：**

| 场景 | 接法 |
|---|---|
| 调代码 / 烧录 | **只插 USB，电池拔掉** |
| 测量试跑 | **只接电池，USB 拔掉** |

**收获：** 这是电源设计的基本纪律 —— **两个电源不能随便并联，除非有专门的电源路径管理电路。** 我宁愿麻烦一点，也不冒烧板的风险。

---

### 6. 屏幕显示异常（SH1106 的列偏移坑）

**问题：** 屏幕点不亮，或者点亮后画面**整体横向抖动**、内容被切掉一列。

**排查过程：** 一度以为是驱动不对，试了 SSD1306 和 SH1106 的各种组合，折腾了很久。

**根因：** 我用的屏是 **SH1106 驱动**，而 SH1106 的显存是 **132 列**，但实际屏幕只有 **128 列** —— 有 2 列是"隐藏"的。所以**列地址必须从第 2 列开始**（`0x02`），如果从 0 开始，画面就会整体偏移，表现为抖动或内容错位。

**解决：** 发送显示数据时把列起始地址改成 `0x02`，画面立刻对齐。

**教训：** **不同驱动芯片的显存布局不一样。** 遇到显示异常，先查驱动的显存结构，而不是盲目换驱动。这个坑让我真正理解了"显存"和"屏幕"是两回事。

---

### 7. 高频串口输出导致主循环阻塞

**问题：** 旋钮"读取串口的时候好用，不读的时候特别难用"，非常诡异。

**排查过程：** 这个坑最难找，因为现象很"玄"—— 它跟功能本身没关系。

**根因：** 我在代码里保留了大量 `Serial.printf` 调试输出。**当没有程序读取串口时，USB CDC 的发送缓冲区会逐渐填满**，一旦填满，`Serial.printf` 就会**阻塞**，卡住整个主循环。于是旋钮中断响应变慢、丢步、卡顿。

**解决：** **正式固件里删掉所有高频调试打印。** 需要调试时再加回来，调完就删。

**教训：** **嵌入式开发里"调试输出"本身就是一个需要管理的资源。** 上线版本的代码，不该有高频打印。这个经验我是用"旋钮莫名其妙不好用"换来的。

---

### 8. 编码器读取的抖动与丢步

**问题：** EC11 旋钮转起来**跳数不准** —— 转一格有时跳两格，有时没反应，逆时针甚至完全失效。

**排查过程（这条是最曲折的）：**

| 尝试 | 结果 |
|---|---|
| 四状态查表 + 主循环 `delay(5)` | 转很多次才有反应，还会回跳 |
| 单下降沿 + 去抖 | 顺时针勉强可用，**逆时针失效** |
| 对称判据（A 降且 B=1 正转 / B 降且 A=1 反转） | 双向可识别了，但仍抖动 |

**根因分析：**

1. **逆时针失效的原因** —— 逆时针转的时候 B 相先下降，等 A 相下降时 B 已经变了，"单下降沿"判据抓不到
2. **抖动的原因** —— 机械编码器在转动时有**触点抖动**，`delay` 轮询会漏掉边沿
3. **一格跳两格的原因** —— EC11 每转一个"咔哒"实际上经历了**完整的四状态循环**，会产生 **2 个有效计数**，如果每次计数都算一步，就会跳两格

**解决（三步）：**

1. **改用 GPIO 中断驱动**（`attachInterrupt` + `CHANGE`），确保不漏任何边沿
2. **中断里做四状态查表**，得到准确的增量方向
3. **软件上累积 ±2 才算一步** —— 抵消"一格两计数"的问题
4. **主循环去掉 `delay`**，编码器读取完全非阻塞

**结果：** 一格一步，顺逆皆准，手感非常好。

**教训：** **机械编码器不是"数字器件"，它有物理抖动。** 用轮询 + delay 去读它，本质上是在赌博。正确做法是中断 + 状态机 + 去抖。这个坑让我第一次真正理解了"中断"为什么重要。

---

### 小结：故障分析给我的东西

回头看这 8 个问题，其实分成四类：

| 类型 | 例子 | 学到的 |
|---|---|---|
| **环境约束** | 不能用烙铁 | 约束会逼出更好的方案 |
| **平台特性** | ESP32-C3 的 USB / strapping 引脚 | 换平台必须重新学，不能想当然 |
| **协议原理** | I2C 总线、SH1106 显存 | 理解原理比记步骤有用 |
| **硬件物理特性** | 编码器抖动、电源倒灌 | 软件不能假设硬件是理想的 |

**最重要的是：** 全程没有老师告诉我答案。**每一次都是"现象 → 猜想 → 验证 → 修正"的循环。** 我觉得这才是这个项目最大的收获。
